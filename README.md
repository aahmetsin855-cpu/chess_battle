# HP Battle Chess

Полностью офлайн 2D тактическая игра на Python 3 + Pygame. **Это не
классические шахматы, хотя фигуры выглядят классически** — белые и
чёрные силуэты, но правила движения, атаки и победы полностью
переработаны: HP, урон, роли фигур, линии огня, большие карты, несколько
игровых режимов (включая туман войны) и локальный ИИ.

«Это не «шахматы с HP». Это большая тактическая битва маленьких армий на
огромном поле, где есть фронт, фланги, дальняя поддержка, тяжёлые юниты,
разведка, тыл, лечение и информационная война.»

Вы всегда играете **белыми**, которые отображаются **внизу доски**. ИИ
играет **чёрными**, наверху доски — как будто вы сидите за своей
стороной шахматного стола. Синий/красный цвет используется **только** в
HP-полосках и минимальных UI-индикаторах (рамка выбора, статус хода) —
сами фигуры остаются классическими белыми/чёрными.

## Установка и запуск

```bash
python -m pip install -r requirements.txt
python main.py
```

Требования: Python 3.8+, Pygame. Для Windows рекомендуется Python 3.13 x64. Никакого интернета и облачных серверов
не требуется — оба варианта ИИ полностью локальны. Фигуры рисуются
процедурно простыми геометрическими фигурами (без изображений), поэтому
игра лёгкая и работает на обычном ПК даже на карте 16x16.

## Поток экранов

```
SELECT GAME MODE  →  SELECT BOARD SIZE  →  расстановка армии  →
SELECT OPPONENT (+ сложность)  →  партия  →  game over
```

Режим игры выбирается ПЕРВЫМ, размер карты — вторым (карта зависит от
контекста режима, поэтому так удобнее планировать партию).

## Local Multiplayer (LAN)

В экране выбора противника появился **Local Multiplayer (LAN)**. Основной сценарий не требует ручного ввода IP:

```text
LOCAL NETWORK

[ HOST GAME ]
[ FIND GAMES ]
[ JOIN BY IP ]
[ BACK ]
```

`FIND GAMES` использует UDP discovery: host отвечает на `HPBC_DISCOVER` сообщением `HPBC_GAME` с именем комнаты, режимом, размером карты и TCP-портом. Ручной `JOIN BY IP` остаётся запасным вариантом.

### LAN-протокол

- `protocol_version = 1`; несовместимые сборки отклоняются явно.
- **Host = White**, **Client = Black**. После подключения клиент получает `welcome` с `player_color = black`, `game_id` и `rules_version`.
- Параметры комнаты (`board_size`, `mode`, `fog_of_war`) фиксируются host до подключения и не меняются внутри сессии.
- Host хранит единственный authoritative `GameState`. Клиент отправляет `action_request`; host проверяет его против `actions.get_legal_actions()`, применяет и рассылает `action_applied` + snapshot.
- Для действий используются `turn_id` и `action_id`; повторная доставка одного действия не применяется второй раз. Для request-ов дополнительно используется `request_id`.
- Сеть передаёт **действия и состояние, а не анимации**. Pygame остаётся полностью вне `network.py`.
- После каждого подтверждённого изменения вычисляется SHA-256 canonical state/view hash. В Fog of War hash клиента строится по его player view, потому что скрытые фигуры вообще отсутствуют в payload.
- В Fog of War скрытые фигуры не отправляются даже как `visible=false`; payload содержит только реально доступный клиенту view.
- При разрыве соединения игра не засчитывает поражение автоматически: клиент пытается переподключиться и запрашивает `resync` snapshot. Host продолжает хранить комнату.
- После `GAME_OVER` в LAN доступны `REMATCH` (только после готовности обоих игроков) и `EXIT`.

Архитектура остаётся общей для будущих оболочек: `game_state.py` / `rules.py` / `actions.py` — игровое ядро, `network.py` / `protocol.py` — LAN, `main.py` — Pygame UI.

| Клавиша | Действие |

| `Esc` | Выйти из игры |
| `F11` | Переключить полноэкранный режим |

## Размер карты

Доступны **10x10** (минимум), **12x12** и **16x16**
(`config.BOARD_SIZE_OPTIONS`). Базовый состав армии остаётся компактным
на 10x10/12x12 — идея в том, что маленькая армия действует на большой
территории: есть пространство для флангов, обхода, разведки, защиты
тыла и подготовки атаки. На самой большой карте (16x16) состав армии
чуть увеличивается (+2 пешки, +1 слон, +1 ладья — см.
`config.get_army_composition()`), иначе фронт получается слишком
разреженным, но рост всё равно умеренный, не "вторая полная армия".

Зона расстановки остаётся компактной независимо от размера карты
(`config.DEPLOYMENT_ZONE_DEPTH`, по умолчанию 3 клетки от домашней
линии) — увеличение карты не растягивает стартовую формацию, а просто
открывает больше пространства для манёвра за её пределами.

Размер карты можно сменить только на экране `SELECT BOARD SIZE` (до
расстановки) — все производные величины (домашние линии, зоны
расстановки, размер клетки/окна) пересчитываются автоматически через
`config.configure_board_size()`.

## Роли фигур

Каждая фигура — не просто "шахматная фигура с HP", а тактическая роль:

- **Пешка — пехота.** Формирует фронт, закрывает линии огня своим телом
  (см. слон ниже), окружает и защищает более ценные фигуры группой.
- **Ладья — танк.** Высокое HP и хороший урон, ломает фронт. Одна пешка
  почти всегда проигрывает ладье в лоб, но несколько пешек вокруг —
  уже серьёзная угроза (совокупный урон против одной цели).
- **Слон — дальняя огневая поддержка.** Атакует область 5x5 вокруг себя,
  но **не может стрелять сквозь фигуры**: если между слоном и целью
  стоит любая фигура (своя или чужая), атака блокируется
  (`rules.has_line_of_sight`). Пешки таким образом получают ещё одну
  роль — прикрывать союзников собой на линии огня. Особенно важно на
  больших картах. Дальняя атака ферзя (RANGED) тоже уважает линию огня.
- **Ферзь — универсальная боевая система с ценой за силу.** Два режима
  (SPLASH убран — ферзь либо двигается, либо становится турелью):
  - **MOVE** — обычное перемещение, ферзь остаётся мобильным.
  - **RANGED** — единственная атака ферзя, дальняя (область 5x5, с
    проверкой линии огня).

  Ключевая идея: **выбор режима RANGED — это отдельное
  действие, которое само по себе завершает ход, ничего не атакуя.**
  Ферзь фиксируется ("превращается в турель") в выбранном режиме и
  теряет возможность двигаться, пока явно не разблокируется отдельным
  действием ('queen_unlock') — выстрел сам по себе режим НЕ снимает,
  ферзь остаётся турелью и может продолжать стрелять дальше без
  повторной фиксации режима каждый ход.
  Хочешь использовать огромную дальность и урон ферзя — сознательно
  жертвуешь его мобильностью, пока сам не решишь выйти из режима.
  Именно поэтому связка Ферзь + Конь
  особенно сильна: конь-щит защищает неподвижную "турель", пока
  противник пытается пробиться через фронт, снять щит и только потом
  добраться до самого ферзя.

  Состояние режима хранится на самой фигуре
  (`Piece.queen_locked_mode`), а не в UI — поэтому оно физически не
  может "сброситься" при повторном рендере или клике; кнопки в панели
  справа только читают/меняют это состояние.

- **Конь — разведчик и щит-усилитель.** Двигается на 2 клетки в любую из
  8 сторон (не буквой «Г»). Не атакует напрямую — «садится» на соседнюю
  союзную фигуру: носитель получает **второе действие за ход**, а конь
  становится щитом (весь урон по носителю сначала достаётся коню). Конь
  может и **слезть обратно** ("спешиться") на соседнюю пустую клетку —
  это отдельное действие, которое тратит **действие самого коня** (не
  носителя), и после этого конь в этот ход больше действовать не может.
  Носитель при этом сразу теряет бонусное действие (если ещё не
  использовал его) и защиту. В UI спешивание — двухшаговое действие:
  сначала кнопка "Спешить коня" в панели выбранного носителя, затем
  клик по одной из подсвеченных соседних пустых клеток.

  HP коня **намеренно не увеличено** вместе с остальными фигурами — его
  сила не в собственной живучести, а в защите и усилении союзника. В
  режиме Fog of War конь — главный инструмент разведки: его мобильность
  позволяет раскрывать карту без специального "радиуса обзора"
  (дальность обзора одинакова у всех фигур, см. ниже).
- **Король — боец и поддерживающий юнит.** Обычные ход/атака (1 клетка,
  8 направлений), плюс действие: **лечение соседней союзной фигуры**
  (выбрать короля → выбрать повреждённого соседа →
  `config.KING_HEAL_AMOUNT` HP). Работает как обычное действие короля —
  как будто "атакует" своего бойца, но это его лечит — и расходует его
  лимит действий за ход, как любое другое.

## HP и баланс

HP увеличены примерно вдвое относительно раннего баланса, чтобы бой
успевал развиваться, а не заканчивался за 1-2 обмена ударами. Все
значения — именованные константы в `config.py`, можно менять:

```python
PAWN_HP = 6
KING_HP = 6
BISHOP_HP = 4
ROOK_HP = 12
QUEEN_HP = 10
KNIGHT_HP = 2   # намеренно НЕ увеличен — см. роль коня выше
```

Урон фигур не менялся.

## Игровые режимы

Выбираются на экране `SELECT GAME MODE` (`config.GAME_MODES`), первым
экраном игры:

### Standard Battle
Классическая цель — полностью уничтожить армию противника
(`GameState.check_victory()`).

### Flag
Не нужно уничтожать всю армию: победа наступает, как только **любая**
ваша фигура достигает вражеской домашней линии. Превращает партию в
`attacking army vs defending army` — заставляет думать о прорыве, а не
только о размене фигур.

**ИИ в этом режиме одновременно наступает и обороняется**: оценка
позиции (`ai._mode_bonus`) поощряет продвижение своей самой дальней
фигуры к цели, отдельно и весомее штрафует за вражескую фигуру,
пересёкшую среднюю линию карты в сторону дома ИИ, и поощряет держать
свои фигуры рядом с этим конкретным "бегуном", чтобы реально его
перехватывать, а не просто проигрывать по счёту, ничего не предпринимая.

### Base / Frontline
У каждой стороны есть тыловая (стартовая) зона. Если вражеская фигура
проникает в неё — лечение для этой стороны **отключается до конца
партии** (`combat.update_base_compromise`, флаг `state.base_compromised`).
Нельзя просто стоять всей армией на одном фронте — тыл нужно защищать.
Индикатор состояния тыла показывается в боковой панели во время партии.

### Fog of War
Ограниченная видимость на большой карте (рекомендуется 12x12/16x16,
но работает на любом размере):

- вы всегда видите свои фигуры;
- вражеский король виден всегда;
- остальные вражеские фигуры видны, только если находятся в пределах
  `config.VISION_RANGE` (дистанция по Чебышеву) от какой-либо вашей
  фигуры — невидимые фигуры **вообще не отрисовываются**;
- дальность обзора **одинакова у всех фигур** (специально, чтобы не
  создавать формального разведывательного превосходства одной фигуры
  над другой — роль разведчика у коня обеспечивается его мобильностью,
  а не особым радиусом);
- если скрытая фигура атакует вас — её позиция временно раскрывается
  (`config.FOG_REVEAL_ON_ATTACK`) до начала следующего хода ИИ.

**ИИ не читерит в тумане войны.** Ход ИИ рассчитывается не на полном
`GameState`, а на "туманной" копии (`fog.build_fogged_view`), из которой
скрытые фигуры игрока физически удалены ещё ДО того, как ИИ начинает
искать ход — поэтому ни minimax, ни LLM-подсказки не могут сослаться на
то, чего ИИ не должен знать. Это гарантия на уровне архитектуры, а не
дополнительная проверка "не забыл ли ИИ спрятать информацию".

## Два режима ИИ

### Algorithm AI (по умолчанию)

Классический локальный поиск, без нейросетей и без интернета:
minimax + alpha-beta + итеративное углубление + transposition table +
сортировка ходов (`ai.py`). Оценка позиции (`eval_state`) учитывает
материал/HP, ценность и защиту фигур, состояние «наездника»-коня,
лечение на домашней линии, контроль центра (масштабируется под размер
карты), развитие фигур в начале партии, угрозы и возможности атаки,
безопасность короля, подвижность, а также специфику текущего режима
(Flag — наступление + оборона зоны + перехват бегуна; Base — штраф за
скомпрометированный тыл).

Сложность (`config.AI_DIFFICULTY_SETTINGS`):

| Уровень | Бюджет времени на ход | Макс. глубина поиска |
|---|---|---|
| Easy | 0.6 с | 3 |
| Normal | 2.0 с | 6 |
| Hard | 4.5 с | 9 |

### Local AI (локальная LLM через Ollama)

Если на компьютере установлена и запущена [Ollama](https://ollama.com):

```bash
ollama pull llama3.2
ollama serve
```

Local AI работает в два уровня:

1. **Teaching / prompt:** перед каждым решением Ollama получает компактные правила HP
   Battle Chess, цель текущего режима, роли фигур, HP/урон, механику короля,
   коня+mount, ферзя, тумана войны и текущую фазу хода.
2. **Tactical player:** дополнительно получает текущее состояние, видимые фигуры,
   последние действия и несколько коротких тактических подсказок. Затем ей
   показывается только список уже легальных `legal_actions[]`, и она должна
   выбрать ровно один индекс.

LLM не обучается изменением весов модели прямо во время партии. Это prompt-based
teaching + игровой контекст. Состояние игры всё равно полностью контролируется
движком: Ollama не может сгенерировать произвольный action или изменить
`GameState` напрямую.

В Fog of War Local AI получает тот же урезанный fog-view, что и Algorithm AI:
скрытые фигуры игрока физически отсутствуют в переданном состояниии.

```python
# config.py
LOCAL_AI_ENABLED = True
LOCAL_AI_MODEL = "llama3.2"
LOCAL_AI_TIMEOUT = 8.0
LOCAL_AI_HOST = "http://localhost:11434"
LOCAL_AI_TEMPERATURE = 0.15
LOCAL_AI_NUM_PREDICT = 12
```

**Игра никогда не падает из-за отсутствия Ollama** — при выборе Local AI
без запущенной Ollama игра автоматически и незаметно использует
Algorithm AI. LLM **никогда не изменяет `GameState` напрямую**:

```
GameState -> Local AI -> предложение хода (индекс из списка легальных
             действий) -> проверка легальности (actions.py) -> GameState
```

Модель получает пронумерованный список уже легальных действий и должна
ответить только индексом; нелегальный/непонятный ответ отбрасывается в
пользу быстрой эвристики.

### Расстановка ИИ (opening formation)

ИИ не расставляет фигуры случайно. `ai.suggest_formation()` генерирует
несколько (`config.AI_FORMATION_SAMPLES`) вариантов формации — пехота
ближе к фронту, тяжёлые фигуры (ладья/ферзь) в тылу, слон/конь в средней
линии зоны расстановки — и оценивает их простой эвристикой, выбирая
лучший вариант. Это **не** жёстко заскриптованный дебют: конкретные
колонки перемешиваются заново в каждом варианте, поэтому расстановка
меняется от партии к партии, сохраняя общую тактическую логику. Та же
функция используется и для формирования стартовой (редактируемой)
расстановки игрока, автоматически масштабируясь под текущий размер
карты и состав армии.

## Память ИИ

После каждой завершённой партии в `data/ai_memory.json` сохраняется
компактная статистика (партии/победы/поражения, предпочитаемые первые
фигуры, использование связки конь+носитель). Не содержит информации о
конкретных ходах игрока — не может использоваться как чит. Короткие
записи об отдельных партиях — в `data/games/game_<timestamp>.json`.
Отключается через `data/settings.json` (`"memory_enabled": false`).

## Настройки

`data/settings.json`, применяются автоматически при следующем запуске:

```json
{
  "ai_type": "algorithm",
  "difficulty": "normal",
  "animation_speed": 1.0,
  "memory_enabled": true,
  "board_size": 10,
  "game_mode": "standard"
}
```

## Анимации

Полностью отделены от логики и от доски. Архитектура рендера
(`renderer.py`):

```
BoardRenderer    — рисует НЕПОДВИЖНЫЕ клетки доски. Никогда не получает
                   данных о фигурах или анимации — физически не может
                   "утащить" фон клетки вместе с фигурой.
PieceRenderer    — рисует силуэт фигуры (классические бело/чёрные цвета)
                   и её HP-полоску/статус. Может принять screen_pos
                   (позиция при анимации), но не трогает фон клетки.
EffectsRenderer  — рисует эффекты атак/попаданий/смерти отдельно от
                   фигур и доски.
AnimationController (animation.py) — хранит и интерполирует ТОЛЬКО
                   экранные координаты фигуры; никогда не трогает
                   координаты самой доски.
```

Ранее существовавший визуальный баг ("клетка едет вместе с фигурой")
был вызван тем, что полупрозрачный оверлей "фигура уже использована в
этом ходу" рисовался по анимированной (движущейся) позиции — из-за чего
казалось, что кусок доски перемещается вместе с силуэтом. Теперь этот
оверлей рисуется только тогда, когда фигура стоит на своей статичной
логической клетке (не анимируется).

Длительности — в `config.py`:

```python
MOVE_ANIMATION_TIME = 0.25
ATTACK_ANIMATION_TIME = 0.20
DEATH_ANIMATION_TIME = 0.30
IMPACT_FLASH_TIME = 0.14
AI_STEP_PAUSE = 0.18
```

Разные эффекты атаки по типу фигуры: короткий удар клинком у пешки/короля,
энергетический снаряд у слона, мощный луч у ладьи, разные эффекты у ферзя
по режиму (сплэш/дальняя), рывок/charge у коня. Ход ИИ выполняется по
частям — каждое атомарное действие видно отдельно (движение → пауза →
следующее действие), а не применяется мгновенно.

## Ход ИИ: state machine + фоновый поток

```
AI_IDLE -> AI_THINKING -> AI_EXECUTING -> AI_FINISHED -> AI_IDLE
```

Расчёт хода (`ai_player.choose_turn_plan`) выполняется в фоновом
`threading.Thread` на КОПИИ состояния (или "туманной" копии в Fog of
War) и никогда не трогает Pygame напрямую. Когда план готов, главный
поток применяет действия по одному к реальному `GameState`, с анимацией
между шагами, и HUD показывает, что именно происходит ("ИИ ДУМАЕТ...",
"ИИ: Атака Ферзь → Слон" и т.д.).

## Интерфейс: устойчивая раскладка панели

Боковая панель и все меню-экраны используют единый вертикальный курсор
(`main.Layout`) вместо ручной арифметики координат — каждый следующий
элемент запрашивает высоту у курсора и автоматически сдвигается вниз.
Это системно устраняет наложение текста/кнопок при переменном
количестве строк (например, у выбранной фигуры может быть 0-3
дополнительные строки статуса — "конь-щит", "может лечить", "режим
ферзя" — и всё, что рисуется ниже, сдвигается соответственно).

## Архитектура

```
config.py         — все константы (HP, урон, таймеры, радиусы, HP-цвета,
                    размеры карты, состав армии по размеру, режимы,
                    сложности ИИ, анимации); configure_board_size()
                    пересчитывает производные величины в рантайме
coords.py          — ЕДИНОЕ преобразование "игровая доска -> экран"
                    (игрок внизу, ИИ наверху); GameState об этом не знает
pieces.py          — класс Piece (включая queen_locked_mode)
game_state.py      — GameState: фигуры, ход, фаза, режим, победа
rules.py           — движение/атака/способности + линия огня слона,
                    цели лечения короля, цели спешивания коня
                    (НЕ шахматные правила)
combat.py          — урон, уничтожение, посадка/спешивание коня,
                    лечение, блокировка/разблокировка ферзя,
                    компрометация тыла (Base/Frontline)
actions.py         — генерация/применение действий (move/attack/mount/
                    dismount/heal/queen_lock/queen_unlock) — общая точка
                    для UI и ИИ
turn_system.py     — стадии хода, таймеры, переход хода
fog.py             — видимость Fog of War + построение "туманной" копии
                    состояния для честного планирования хода ИИ
ai.py               — Algorithm AI: minimax + alpha-beta + iterative
                    deepening + transposition table + оценка позиции
                    (материал, роли, режимы) + suggest_formation()
ai_interface.py     — общий интерфейс AIPlayer: AlgorithmAI и LocalAI
ai_memory.py        — компактная память ИИ (data/ai_memory.json)
settings.py         — настройки игрока (data/settings.json)
animation.py         — контроллер анимаций (только экранные координаты)
renderer.py           — BoardRenderer / PieceRenderer / EffectsRenderer
main.py               — экраны (режим, размер карты, расстановка,
                    противник), ввод, state machine хода ИИ, Layout-курсор
tests.py              — регрессионные тесты
```

Логика (`pieces.py`, `game_state.py`, `rules.py`, `combat.py`,
`actions.py`, `turn_system.py`, `fog.py`, `ai.py`, `ai_interface.py`,
`ai_memory.py`, `settings.py`, `coords.py`, `animation.py`) не зависит
от Pygame.

### Добавление новых механик

Новое правило — ещё один тип действия в `actions.py`
(`get_legal_actions`/`apply_action`), расчёт целей — в `rules.py`,
эффект — в `combat.py`. `ai.py` автоматически учитывает новые действия
через `get_all_legal_actions`. Для UI, если у действия есть целевая
клетка на доске — используйте `build_action_map`; если действие
двухшаговое (сначала "вооружить", потом выбрать клетку/цель, как
dismount) или не привязано к клетке (как queen_lock/queen_unlock) —
заведите отдельный список наподобие `special_actions`/`dismount_options`
вместо смешивания в общую карту (чтобы избежать коллизий клеток). Для
анимации — вызов соответствующего `animation.start_*`/`spawn_*` в
`main.py.apply_action_with_animation`.

## Recent LAN/UI/AI updates

- LAN client snapshot diagnostics now hash the same player-specific Fog of War view supplied by the host. This prevents false DESYNC reports when hidden enemy pieces are omitted.
- Reconnect retires the previous TCP peer before opening a new connection, preventing stale reader threads from injecting late `disconnected` events.
- Custom knight movement now requires the intermediate cell to be empty. The rule lives in `rules.py`, so player, AI, Local Multiplayer, and future clients share it.
- Healing is explicitly scored by the Algorithm AI instead of being treated as an incidental low-HP case.
- AI formation scoring now penalizes deployments that lock knights and rewards multiple available knight directions.
- Added requested board presets: 10x10, 12x12, 16x16, while keeping the small-army-on-large-field concept.
- Added a proper minimalist main menu with Play / Local Multiplayer / Settings / Exit.
- Fullscreen is persisted in `data/settings.json` and toggled with F11.
- UI active states use a neutral monochrome accent; blue/red remain reserved primarily for player/enemy HP semantics.

### LAN sync rule

For Fog of War, the host sends a hash of the exact player view:

`host: state_hash(state, viewer_color="black")`

and the client verifies the same view:

`client: state_hash(state, viewer_color=self.player_color)`

The host continues to keep the complete authoritative GameState; hidden pieces are never sent to the client.

The project regression suite currently passes **36/36** tests in the available headless environment. Pygame-dependent visual tests are skipped here when Pygame is unavailable and must still be checked on a machine with Pygame installed.


## LAN-мультиплеер

На первом ПК выберите **Мультиплеер по сети → Создать комнату**. Игра покажет локальный IP и порт. На втором ПК выберите **Мультиплеер по сети → Подключиться по IP**, введите IP первого ПК и тот же порт. Хост играет белыми, подключившийся игрок — чёрными. Для автоматического поиска можно использовать **Найти комнаты**, если broadcast UDP разрешён локальной сетью.

Порты: TCP `38478`, UDP discovery `38477`. Если Fedora/firewalld блокирует соединение, откройте их на компьютере-хосте:

```bash
sudo firewall-cmd --permanent --add-port=38478/tcp
sudo firewall-cmd --permanent --add-port=38477/udp
sudo firewall-cmd --reload
```

## Полный экран

Полноэкранный режим является режимом по умолчанию. Игра получает нативное разрешение монитора через SDL; `F11` переключает полноэкранный/оконный режим. Размер карты меняет размер клеток, но не создаёт новое окно при переходе между экранами.

## Слон и линия огня

Слон теперь может стрелять **через союзные пешки**, но не через другие союзные фигуры. Вражеская фигура на линии огня также блокирует выстрел. Это делает именно союзную пешку особым элементом прикрытия, не превращая правило в полное отсутствие блокировки.


## LAN: порядок создания комнаты

На хосте кнопка «Создать комнату» больше не запускает пустую/неуправляемую
доску сразу. Правильный поток:

`Мультиплеер по сети → Создать комнату → Режим → Размер карты → Расстановка → Комната создана → ожидание второго ПК → Партия`.

До подключения второго игрока игровая доска не показывается как активная
партия. На экране ожидания отображаются IP, порт, выбранный режим и размер
карты. После подключения обоих игроков автоматически начинается партия.

### Ладья: обмен местами
Ладья получила специальное действие `rook_swap`: при выборе ладьи подсвечиваются соседние живые союзные фигуры. Клик по такой клетке меняет местами ладью и выбранную фигуру и расходует одно действие ладьи. Действие самой перемещённой фигуры не расходуется; конь-щит следует за своим носителем.

### Визуальный урон
При атаке рядом с фактически получившей урон фигурой появляется красное плавающее число (`-N`), которое поднимается и исчезает.
