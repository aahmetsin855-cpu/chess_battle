# Сборка под Windows x64 (PyInstaller)

## Важная оговорка

PyInstaller **не кросс-компилирует** — он упаковывает интерпретатор и
библиотеки той машины, на которой запущен. Собрать `.exe` для Windows
можно только **на самой Windows** (обычной или в виртуалке/CI-раннере
с Windows). Всё, что подготовлено в этом коммите (`hp_chess.spec`,
`build_windows.bat`, фиксы ниже) — это то, что нужно, чтобы сборка на
Windows прошла чисто и не сломалась именно по причинам, специфичным для
frozen-приложений. Сам `.exe` собрать и руками прогнать чек-лист должен
кто-то с доступом к Windows-машине — тут результата PyInstaller.exe
приложить не могу.

## Что было исправлено специально под PyInstaller

1. **Диалог выбора файла (музыка/фон) больше не завязан на внешний
   `python.exe`.** Раньше он запускался как `sys.executable -c
   <скрипт>` — это ломается в собранном приложении, потому что там
   `sys.executable` это САМ `.exe` игры (отдельного интерпретатора
   внутри onedir-сборки нет), и `-c` для него — просто мусорный
   аргумент запуска, а не флаг питона. Теперь `.exe` умеет запускать
   **сам себя** в лёгком режиме `--file-dialog-helper` (см. самый верх
   `main.py`) — работает одинаково что в сборке, что из исходников, и
   не трогает pygame/SDL вообще.
2. **`config.BASE_DIR` (папка для `data/settings.json`,
   `data/ai_memory.json`, `data/games/`) теперь использует
   `sys.executable`, а не `__file__`, когда приложение собрано
   (`sys.frozen`).** `__file__` в frozen-сборке указывает внутрь
   бандла (например, в `_internal` при `--onedir`), а не туда, где
   реально лежит `.exe` и куда ожидается писать данные — эта папка
   может быть даже недоступна на запись. `sys.executable` в
   PyInstaller всегда указывает на настоящий путь установки.

Больше никаких платформенных хаков в коде нет — LAN (`network.py`,
чистый `socket`/`threading`), обнаружение Ollama (`urllib.request` по
`http://localhost:11434`) и весь рендеринг (`pygame`, без внешних
файлов-ассетов — все фигуры рисуются `pygame.draw`, шрифт —
встроенный `pygame.font.Font(None, ...)`) кросс-платформенны сами по
себе и не требуют Windows-специфичного кода.

## Сборка

Требования: **Python 3.13 x64** на Windows (`py -3.13` должен быть
доступен из `py launcher`).

```
build_windows.bat
```

Скрипт сам: создаёт venv (`.buildvenv`), ставит `pyinstaller` и
`requirements.txt` (`pygame==2.6.1`), чистит `build/`/`dist/`, собирает
через `pyinstaller --noconfirm hp_chess.spec` (`--onedir --windowed`,
`target_arch='x86_64'`).

Результат: `dist\HP Battle Chess\HP Battle Chess.exe` — вся папка
`dist\HP Battle Chess\` и есть портативная сборка, переносить нужно
целиком, не только `.exe`.

Если `pip install pygame==2.6.1` не найдёт колесо под Python 3.13
(бывает в первые месяцы после выхода новой версии Python, пока не
все пакеты дособрали wheel'ы) — обновите версию в `requirements.txt`
до последней доступной `pygame` (2.6.x/2.7.x), это не потребует
изменений в коде игры.

## Чек-лист ручной проверки (обязательно перед финальным билдом)

Сначала собрать и прогнать чек-лист именно на `--onedir --windowed`
сборке (быстрее итерировать, консоль при падении можно временно
включить, поставив `console=True` в `hp_chess.spec` и пересобрав —
тогда traceback будет виден, а не только тихо закрывшееся окно).

- [ ] `HP Battle Chess.exe` запускается, открывается главное меню.
- [ ] "Новая игра" -> выбор режима -> выбор размера доски -> расстановка
      армии -> подтверждение -> партия действительно начинается.
- [ ] Настройки открываются, значения (сложность ИИ, скорость анимаций,
      полноэкранный режим) сохраняются между запусками (значит,
      `data\settings.json` реально создаётся и пишется рядом с `.exe`
      — если файла нет, ищите `config.BASE_DIR`, см. фикс выше).
- [ ] Кнопка выбора музыки открывает системный диалог, выбранный файл
      реально начинает играть; то же для фона.
- [ ] Диалог выбора файла: открыть, ЗАКРЫТЬ БЕЗ ВЫБОРА (крестиком и
      отдельно кнопкой "Отмена"), затем открыть СНОВА — должен
      появиться повторно (это был баг, актуально перепроверить именно
      в собранном виде).
- [ ] LAN: два экземпляра `HP Battle Chess.exe` на одной машине (или на
      двух в одной сети) — один "Создать игру", второй "Найти игру" —
      находят друг друга, подключаются, ход противника приходит и
      анимируется. При первом запуске Windows Defender Firewall
      покажет запрос доступа к сети — нужно разрешить (см. ниже).
- [ ] Если на машине установлена Ollama — в настройках ИИ опция
      "Локальный ИИ" должна определяться как доступная (см. ниже).
- [ ] Полноэкранный режим (F11) переключается без зависаний; свернуть
      игру и открыть, например, Проводник поверх неё — не должно
      зависать (это тоже был отдельный баг, специфичный для
      эксклюзивного fullscreen — теперь используется borderless-окно
      на весь экран, не эксклюзивный режим).

После того как всё выше пройдено на `--onedir` — финальный билд можно
раздавать as-is (`--onedir` и есть финальная поставка: папка целиком).
Если нужен ИМЕННО один `.exe`-файл (`--onefile`), это отдельный
профиль сборки со своими нюансами (распаковка во временную папку при
каждом запуске, чуть медленнее старт) — дайте знать, добавлю отдельный
`.spec` под это, тестировать заново весь чек-лист всё равно придётся.

## LAN на Windows — чего ожидать

Код LAN (`network.py`) использует только стандартные, кроссплатформенные
сокеты (`AF_INET`/`SOCK_STREAM` для TCP-соединения, `SOCK_DGRAM` +
`SO_BROADCAST` для обнаружения игр в сети) — ничего Linux-специфичного
там нет, `SO_REUSEPORT` (которого на Windows вообще нет) не используется.
Единственное, что реально отличается на Windows:

- **Windows Defender Firewall** при первом запуске почти наверняка
  спросит, разрешить ли `HP Battle Chess.exe` доступ к частным и/или
  публичным сетям — нужно поставить галочку хотя бы на "частная сеть"
  (эта часть уже описана в `WINDOWS.md`, но с ней придётся столкнуться
  и на собранном `.exe`, а не только при запуске из исходников).
- Если брандмауэр промахнётся с запросом (бывает при первом запуске
  собранного `.exe`, если Windows ещё не проиндексировала бинарник) —
  добавить разрешение вручную: Параметры -> Конфиденциальность и
  защита -> Брандмауэр Windows -> Разрешить приложение через
  брандмауэр -> добавить `HP Battle Chess.exe`.
- Обнаружение игр по UDP-broadcast работает только внутри одной
  подсети (стандартное ограничение broadcast, не специфика игры) —
  прямое подключение по IP (уже реализовано в игре как отдельный
  способ) сработает и между разными подсетями, если порт проброшен/
  доступен.

Дать стопроцентную гарантию, что LAN заработает именно на конкретной
Windows-машине пользователя (там могут быть корпоративные политики,
сторонние антивирусы с собственным файрволом и т.п.), без доступа к
этой машине невозможно — но сам код не содержит платформенных
причин для отказа.

## Ollama на Windows — чего ожидать

`check_ollama_available()` (`ai_interface.py`) стучится по обычному
HTTP на `http://localhost:11434/api/tags` через `urllib.request` —
это стандартная библиотека, PyInstaller подхватывает её автоматически,
никаких скрытых импортов не требуется. Условия для срабатывания:

- Официальный **Ollama для Windows** должен быть установлен и запущен
  (это отдельное, не входящее в игру приложение — Ollama сама поднимает
  локальный сервер на `11434`, так же как на Linux/macOS).
- Loopback-трафик (`localhost`) в Windows по умолчанию не режется
  брандмауэром вообще (это не "сетевой" трафик в смысле файрвола), так
  что дополнительных разрешений для самого обнаружения Ollama обычно
  не требуется — в отличие от LAN-игры, которая ходит по настоящей
  сети.
- Если Ollama слушает не порт по умолчанию или запущена на другой
  машине в сети — поменяйте `config.LOCAL_AI_HOST` под фактический
  адрес.

Если `check_ollama_available()` вернёт `False` (Ollama не запущена,
не установлена, или отвечает не сразу), игра автоматически и без
падений переключается на `AlgorithmAI` (см. `LocalAI.__init__` в
`ai_interface.py`) — это уже было в коде и не требует доработки под
Windows отдельно.
